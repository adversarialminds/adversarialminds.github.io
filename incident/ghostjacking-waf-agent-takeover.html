Kill-chain analysis

Initial AccessIndirect (I)
The attacker posts crafted events to Sentry's public ingest API, and the victim's agent later reads them through its integrations.
We inject stacktraces into Sentry's public API, no auth needed. defcon.org/html/defcon-34/dc-34-speakers.html (talk abstract, Chain 2)
Priv. Esc.Social eng. (SE)
Blunt commands were refused, so the payloads were disguised as scanner findings or vendor remediation guidance that the agent trusts.
What worked was structured scanner telemetry: a ticket reference, a compliance-framework citation, and an unfalsifiable metric, a finding with a gap, never a command. tenetsecurity.ai/blog/ghostjacking-attacks-agentic-kill-chain/ § 1. The firewall blocked the attack
Recon.—not demonstrated
Persist.Dependent (channel)
The injection stays in logs and error events the attacker can write to and fires whenever an agent reads them.
Just text in public logs, waiting to be read. defcon.org/html/defcon-34/dc-34-speakers.html (talk abstract)
C2—not demonstrated
Lat. Mov.Cross-app (xA)
Sentry's Seer agent is compromised first, and its poisoned recommendation is then executed by a separate coding agent.
Sentry's "Seer" agent reads them, gets compromised, and its poisoned recommendations flow into a developer's Cursor which executes our commands. One agent infecting another. defcon.org/html/defcon-34/dc-34-speakers.html (talk abstract, Chain 2)
Action on Obj.RCE
The coding agent installs and loads the attacker's npm package, running attacker code on the developer's machine.
Impact: RCE on the developer’s machine with no “run this” and no contact with the victim tenetsecurity.ai/blog/ghostjacking-attacks-agentic-kill-chain/ § 3. Attack that jumps from one AI Agent to another agent
